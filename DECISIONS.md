# Decisions and assumptions

Dated log of the calls made while building this, so Carlo can see the reasoning and overrule any of them.

| Date | Decision | Why |
|---|---|---|
| 2026-09-29 | End-to-end first, breadth second | The brief grades the system, not a list of famous names. The pipeline is run on a real seed and the first entries are fully evidenced; the same pipeline then fills the rest on a schedule. |
| 2026-09-29 | Two X data sources behind one interface | The official X API (pay-per-usage, compliant, has user search and verified flags) for verification, evidence and precise search; monid (proxying Apify actors, about 25x cheaper per profile) for bulk follower and following crawls. Either alone can run the whole pipeline. |
| 2026-09-29 | Read-only by construction | The X adapter uses an app-only token with no write scopes. The system cannot follow, DM or post. The brief says nobody gets contacted. |
| 2026-09-29 | Map mirrored through its JSON API, not scraped from pixels | network.ri.fo serves `/api/graph`, `/api/timeline` and `/api/wishlist`. Ingestion logs in with the passphrase from `.env` and mirrors capital and press into SQLite. Notes, events and summaries are not exposed by the map and are not needed. |
| 2026-09-29 | Output also in the map's own wishlist shape | The map has a hidden wishlist tab that renders `n, name, role, section, paths[{how, you, via, warmth, target}]`. `data/exports/wishlist.json` follows that shape so Carlo can load it there. |
| 2026-09-29 | Claude via the Claude Code CLI as the default LLM backend | Carlo confirmed Claude may be used on map and scraped data. The CLI needs no API key; the Anthropic API backend is a switch in `.env`. No standalone agents: scheduled automations that call an LLM where judgement is needed (classification, evidence extraction). |
| 2026-09-29 | Unknown stays unknown | Probabilities start from low, explicit priors per category and only move with evidence rows that quote a real post, profile field, investment or article. Confidence reports how much of the score is evidence rather than prior. |
| 2026-09-29 | Competitor ties are flagged, never hidden | Per the brief. The flag carries the competitor, the kind of tie and the evidence; the dashboard shows it. VCs are also checked against the map's competitor-fund table. |
| 2026-09-29 | Audience is US only | Confirmed by Federico. Candidates with a non-US location are flagged `not_us` and rank low; unknown location stays unknown. |
| 2026-09-29 | Attention > network > funding | Confirmed priority for an October launch. Encoded in the impact factor's role weights (see SCORING.md). |
| 2026-09-29 | Paths are real relationships | A follow alone is never a path. Paths come from the map (warmth, meetings, intro edges, LinkedIn connection) and from X conversations (replies, mentions) or mutual follows with the seed; a connector-candidate mutual follow is shown but capped at low strength. |
| 2026-09-29 | Local scheduler, not GitHub Actions | The brief keeps map data on Carlo's machine. `scripts/install_schedule.sh` installs a daily launchd job; a cron line is documented for Linux. |
| 2026-09-29 | Data lives in the repo, repo stays private | The brief asks for code and data in one repository they can run. `.env` (keys, passphrase) is git-ignored. |
| 2026-09-29 | monid endpoints pinned after live probes | `apify /kaitoeasyapi/premium-x-follower-scraper-following-data` for follow lists ($0.000225 per row, both caps must be at least 200), `apify /apidojo/tweet-scraper` for search and evidence posts ($0.0006 per post, each tweet carries the full author profile), `tikhub fetch_user_profile` for single profiles ($0.0015). The Apify user scraper assumed in the first plan does not exist on monid. |
| 2026-09-29 | Official X API only for verification | Follow lists cost $10 per 1,000 rows there and user search needs a user-context token. The official API does what it is best at: confirming that a handle still belongs to the same numeric account ($0.01 per user, batched). |
| 2026-09-29 | Handles of Carlo's contacts are matched against his own follow lists | Map people tagged `x_following` must appear in Carlo's following list, `x_follower` in his followers. Matching names there is free and proves a real X relationship, unlike a name search that can land on a namesake or a parody. Paid search is a bounded fallback. |
| 2026-09-29 | Tweet authors are cached as profiles | Every scraped post includes its author's profile, so discovery never pays for a separate lookup of a person it found through a post. |
| 2026-09-29 | Follow lists are cached for seven days | Re-runs read the stored lists instead of buying them again (`FORCE_REFRESH=1` bypasses). The daily schedule therefore spends on new search results, not on the same graph. |
| 2026-09-29 | Transparency: one accidental live read of the map | During development a test of the refresh path logged in to network.ri.fo once with the passphrase from `.env` and re-read the map (read-only; the content was identical to the morning export). A DRY_RUN guard and a test fixture now make that impossible from tests. |
| 2026-09-29 | Quality over connection: a path is information, not a requirement | Carlo (via Federico, 29 Sep afternoon): rings may go to people outside the map. The brief's "a name nobody can reach does not belong" is overruled. Reach leaves the total; a real warm relationship only nudges P(accept), and having no path never penalises. The `unreachable_celebrity` enrich gate is removed and a map link weighs less in enrichment priority. Paths are still computed and shown so Carlo knows how to approach each person. Four QA rejections that rested on "no path" were reversed (@mkbhd, @steventey, @vadimyuryev, @iam_agg). |
| 2026-09-29 | Handles of map contacts found by web search, confirmed by id | `config/handle_overrides.yaml`: 95 of 142 searched map people have a handle (79 verified, 16 likely), each checked on the official X API ($1.06); 47 stay unknown. |
| 2026-09-29 | One list; weights hidden behind a Manual weights switch | The list ranks with the default weights (SCORING.md, or a `default:` saved in `config/weights.yaml`). "Manual weights" shows the sliders and a Run button that re-ranks the stored factors in under a second at no cost, so priorities can be changed live with Carlo. Two tabs showing the same list two ways confused more than they helped. |
| 2026-09-29 | Check an account on demand | Carlo can name anyone: the dashboard previews the cost (about $0.03), and after Accept it fetches, classifies and scores that account with the same code and says where it would rank and why. A checked account becomes a normal candidate; "Keep off the wishlist" excludes it. |
| 2026-09-29 | Discovery beyond keywords: people our best people follow | A check of @simonw (227k followers, writes daily about AI agents) put him at #10, yet the system had never seen him: he is not in Carlo's graph and none of his posts made the top 100 of the 23 narrow searches. Recall depended on a small sample of posts. A new `expand` stage pulls who the best-evidenced people on the list follow and adds accounts followed by at least three of them; about 12 new searches with an engagement floor favour people with an audience. |
| 2026-09-29 | The bar is a rule, and the list is the people who meet it (65), not a padded 100 | The brief: "someone who has never worn a device or used a voice tool does not belong on the list however big they are" and "a shorter list with real evidence beats a hundred names with adjectives". Three hand reviews rejected more than half of each batch that reached the top 100 on reach alone (outlets, crypto and promo accounts, famous people with no device use). The list is now the people in a person category (X voice, media, VC, founder or angel) with net positive evidence of wearing a device or using a voice tool, US or unknown, not rejected: 65 on 29 Sep, every one reviewed by hand. The dashboard can switch the rule off to see everyone else. |
| 2026-09-29 | The bar includes reach: every person on the list has a contact route | The brief: "A name nobody can reach, or someone who has never worn a device or used a voice tool, does not belong on the list however big they are." Carlo may approach people cold, so a warm path is still not required, but each person needs at least one real way to be contacted: a warm path, open X DMs (or they follow Carlo), a public route found by research (`config/contact_routes/*.yaml`, with the page it was found on), or an email in their X bio. Weak routes are labelled "(weak)"; unconfirmed ones never count alone. The dashboard shows how ("How to contact"), the export carries the routes, and anyone without one leaves the list with the reason. On run 42: 64 of the 65, @iam_agg out. |
| 2026-09-30 | Community engagement is its own factor in the total, measured per follower against accounts of the same size | Federico asked for engagement in raw numbers and arithmetic: views, likes, comments and reposts of the average post ÷ followers. The stored posts could not answer it: enrich's searches rank by engagement, so they are each person's best posts. A sample of their latest 30 original posts is fetched instead (about $0.018 a person), and the average is trimmed so one viral post cannot carry it. Raw per-follower rates fall as followers grow, so each rate is compared with the rate typical for the person's size (a fit on every sampled account); replies and reposts weigh most because a ring post that gets answered and reposted travels. The total gains ×(0.7 + 0.6 × engagement): ×1.0 for a typical community or when unknown, ×0.7 to ×1.3 otherwise. It has its own slider (Community engagement) so Carlo can turn it up, down or off live. It is not part of the bar: a quiet audience lowers a score, it does not remove a person. |
| 2026-09-30 | Open X DMs count once seen | X's `canDm` on a scraped author depends on the account that loaded the page: in the engagement sample, 23 of the 64 read open on some posts and closed on others, and the last post stored won, so a fetch could silently drop someone's only contact route (8 fell below the bar on the first rescore). Any sighting of open DMs now counts and a later 'closed' does not erase it (sources.base.persist_users; backfilled from stored posts and earlier open_dm paths). The researched routes stay listed as second routes. |
| 2026-09-30 | Competitor ties are flagged, never removed | The brief: "Anyone tied to a direct competitor (...) is flagged." Hand reviews had rejected 16 people for the tie itself (founders and CEOs of Rabbit, Sandbar, Wispr Flow, Omi, Friend, Pebble; investors who led their rounds), and the enrichment gate skipped anyone whose bio named a competitor role, so they never got evidence. Federico, 30 Sep: flag them, don't remove them. The 16 are back as candidates (their old notes kept), the gate is gone, and four ties the reviews found but the flag missed are in `config/competitor_ties.yaml` with sources (Forerunner's Oura stake, Ohanian's Willow Voice angel check, Every's Monologue for Dan Shipper, Brian Roemmele's GrokPod). A tie still lowers p_accept through its evidence; the Flags column shows it next to the category; Filters can hide competitor-tied people. People rejected for other reasons (no evidence, affiliate promotion) stay rejected. |
| 2026-09-30 | Non-US people are evaluated like everyone; "US only" is a view filter | The enrichment gate skipped anyone whose X location was outside the US, so non-US people never had device or voice evidence and all fell below the bar: turning "US only" off showed nobody new. Federico, 30 Sep: the toggle must show non-US people and reorder the list. The gate is gone, and the 266 non-US people discovery had found were enriched and classified (approved scope, about $5.60 with their engagement samples). The default list stays US only. |
| 2026-09-30 | Discovery searches for evidence first: a new `evidence` query group | The list stopped at 79 and every person on it needs a first-person post about wearing a device or using a voice tool. The earlier groups search topics, so the author still needs the evidence found later: 2.3% (topics), 3.0% (competitor products) and 3.4% (authors) of the people they surfaced made the list, and the groups without a like floor spent about three quarters of their posts on posts under 50 likes. The 20 `evidence` queries look for the person's own words ("my Oura", "wearing my", "Hey Meta", "I dictate", voice mode on a walk or a drive, AirPods with ChatGPT) across rings, Whoop, Apple Watch, Meta glasses, pendants, dictation apps and voice mode, with the brands' own accounts excluded. The floor comes from the list's 137 wear posts (median 85 likes): min_faves:50 keeps the best wear post of 49 of the 73 people who have one, the authors floor of 200 only 27; mass-market products use 100. At most $1.20 a run; it runs in the weekly discover. First run (30 Sep, run 58): $0.79 for 1,319 posts by 988 authors; 58 of them joined the list after review (79 to 137), step C $3.72 in all. |
